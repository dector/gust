gust ctl - control a running instance

Usage:
  gust ctl [-S <socket>] <command>

Commands:
  status    show instance state and last exit
  probe     list running instances and their URLs (no -S)
  pause     pause filesystem auto-reload
  resume    resume filesystem auto-reload
  rerun     reload now (works while paused)
  logs      show output captured from the last failed exit
  comments  wait for, recover, reply to, or review submitted comments
  help      show the ctl help

Discovery:
  Without -S, the socket path is derived from the current directory.
  probe instead scans all sockets in the per-user directory, from any directory.

Samples:
  gust ctl status
  gust ctl probe
  gust ctl pause
  gust ctl rerun
  gust ctl resume
  gust ctl logs
  gust ctl comments
  gust ctl comments --filter all
  gust ctl comments --filter done,review
  gust ctl comments --wait
  gust ctl comments --wait --one
  gust ctl comments --pending
  gust ctl comments seen <id>
  gust ctl comments reply <id> <text>
  gust ctl comments reply <id> <text> --human
  gust ctl comments review <id> <text>
  gust ctl comments done <id>
  gust ctl -S /tmp/gust-1000/abc.sock status

Comment handoff:
  comments --wait blocks for the oldest submitted batch and marks its
  comments seen. With --one it claims only the oldest submitted comment
  from that batch; repeat to consume remaining comments at your own pace.
  Output keeps the batch JSON shape with one comment. comments seen <id>
  claims one submitted thread without waiting for a batch. comments lists all
  unfinished comments (created, submitted, seen, and review). comments
  --pending lists only seen, unfinished comments for recovery after an
  interrupted agent. comments --filter <states> limits the list to the given
  states (all, or a comma-separated list of created, submitted, seen, review,
  done); "all" includes resolved threads. The agent
  posts a reply on a seen thread with reply, or posts a reply and marks the
  thread review with review. Only the human resolves a thread, with done.
  reply --human records the reply as a human reply; a human reply to a review
  thread reopens it as submitted for the agent.
  Comments persist across restarts in a per-project state file.

Typical agent flow:
  gust ctl pause        # stop filesystem-triggered reloads
  # edit files
  gust ctl rerun        # start the app with your changes
  gust ctl resume       # resume auto-reload (reloads if changes were missed)

Exit codes:
  0  success
  1  could not reach or control the instance
  2  usage error
